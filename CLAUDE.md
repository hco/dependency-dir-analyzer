# CLAUDE.md

Guidance for Claude Code (and humans) working in this repository.

## What this project is

`dependency-dir-analyzer` is a cross-platform CLI tool written in Rust. It scans
a directory tree, finds **dependency directories** — folders generated by package
managers and build tools that can usually be regenerated from source, such as
`node_modules`, `target`, `.venv`, `vendor`, `.gradle` — and reports how much disk
space each one uses and when it was last modified.

On a terminal the default output is an interactive, live-updating TUI (built on
`ratatui` + `crossterm`) that streams results in as they are found and sized.
From the TUI you can also mark directories and delete them — to the system trash
by default (via the `trash` crate) or permanently — behind a confirmation
dialog. When the output is piped/redirected — or with `--plain` — it prints a
plain aligned table; `--format json` and `--format csv` are always
non-interactive. Shell completions are available via `dda completions <shell>`.

The installed binary is named **`dda`** (the crate is `dependency-dir-analyzer`).

## Toolchain & tasks: use mise

This repo uses [mise](https://mise.jdx.dev) both to install the toolchain and as
the task runner. The Rust version is pinned in `mise.toml`.

```bash
mise install        # install the pinned Rust toolchain
mise tasks          # list available tasks
mise run build      # cargo build
mise run test       # cargo test
mise run lint       # cargo clippy -D warnings
mise run fmt        # cargo fmt --all
mise run fmt-check  # cargo fmt --all --check
mise run ci         # fmt-check + lint + test + release build (what CI runs)
mise run run -- ~/code   # run the CLI against ~/code
```

Prefer `mise run <task>` over invoking `cargo` directly so behaviour matches CI.
If you add a workflow developers will repeat, add it as a task in `mise.toml`.

## Layout

```
src/
  main.rs       # CLI entry point: parse args, pick TUI vs batch, dispatch output
  cli.rs        # clap argument definitions, `completions` subcommand, `parse_size`
  scanner.rs    # filesystem walk, patterns, parallel sizing, batch + streaming APIs
  report.rs     # Report struct + table/JSON/CSV rendering, size & age formatting
  tui.rs        # interactive live-updating ratatui UI (consumes the streaming scan)
  state.rs      # persisted TUI view prefs (sort/group/filters), keyed by scan root
.github/workflows/
  ci.yml        # lint/test/build on Linux, macOS, Windows via mise
  release.yml   # cross-compiled release binaries on tag push
.claude/
  hooks/session-start.sh   # installs mise + deps in Claude Code on the web
  settings.json            # registers the SessionStart hook
demo/
  demo.tape       # VHS script for the README GIF (`mise run demo`)
  make-fixture.sh # builds the git-ignored fake project tree the demo scans
  demo.gif        # committed; rendered output the README links to
mise.toml       # toolchain + tasks
```

## How the scanner works

- `scanner::PATTERNS` is the list of known dependency-directory names mapped to
  an ecosystem label. To support a new tool, add an entry there (and ideally a
  test case). Matching is by **exact, case-sensitive base name**.
- When a matching directory is found, the walk does **not** descend into it: the
  whole subtree is sized as one unit, so a nested `node_modules` inside another
  is not double-counted.
- Sizing is parallelised across matches with `rayon`. While sizing a subtree the
  scanner also tracks the most recent mtime, which is what the "modified" column
  and the relative-age display ("3d ago") report.
- There are two entry points: `scan` returns the full sorted `Vec` in one shot
  (used by the JSON/CSV/plain paths and tests), and `scan_streaming` sends
  `ScanEvent`s (`Discovered` → `Sized`) over a channel as it goes, which is what
  the TUI consumes on a background thread to render results live.
- Unreadable entries produce a warning (on stderr in batch mode, or in the TUI
  footer) and are skipped; the scan does not abort.

## Conventions

- Keep `cargo fmt`, `cargo clippy -D warnings`, and `cargo test` clean — CI
  enforces all three. Run `mise run ci` before pushing.
- Add unit tests next to the code (`#[cfg(test)] mod tests`) for new behaviour.
- Keep dependencies minimal and pure-Rust where possible so cross-compilation
  stays painless.

## Releases

Releases are driven by [`dist`](https://opensource.axo.dev/cargo-dist/)
(formerly cargo-dist). Config lives in `dist-workspace.toml`; the pinned `dist`
version is in `mise.toml` (`cargo-dist`) and the CI workflow
(`.github/workflows/release.yml`) is **generated** from that config — never
hand-edit it. When a `v*.*.*` tag is pushed, `dist` cross-compiles for Linux
(x86_64, aarch64), macOS (x86_64, aarch64) and Windows (x86_64), attaches
archives + SHA-256 checksums to a GitHub Release, and publishes a Homebrew
formula (`dda`) to the `hco/homebrew-tap` repo so `brew install hco/tap/dda`
works.

To cut a release:

```bash
# bump version in Cargo.toml first, then:
git tag v0.1.0
git push origin v0.1.0
```

After changing `dist-workspace.toml` or bumping the pinned `cargo-dist` version
in `mise.toml`, regenerate the workflow and commit the result:

```bash
dist generate            # rewrites .github/workflows/release.yml
dist generate --check    # CI-style check that it is up to date
```

**One-time setup for the Homebrew tap** (already documented, must exist for the
publish job to work): a `hco/homebrew-tap` GitHub repo, plus a
`HOMEBREW_TAP_TOKEN` Actions secret (a PAT with write access to that repo) in
this repository — the default `GITHUB_TOKEN` cannot push to another repo.

## Claude Code on the web

`.claude/hooks/session-start.sh` runs at session start in the remote
environment (`CLAUDE_CODE_REMOTE=true`). It installs mise if absent, runs
`mise install`, and puts the toolchain on `PATH` so tests and linters work
immediately. It is a no-op locally.
