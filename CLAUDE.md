# CLAUDE.md

Guidance for Claude Code (and humans) working in this repository.

## What this project is

`dependency-dir-analyzer` is a cross-platform CLI tool written in Rust. It scans
a directory tree, finds **dependency directories** — folders generated by package
managers and build tools that can usually be regenerated from source, such as
`node_modules`, `target`, `.venv`, `vendor`, `.gradle` — and reports how much disk
space each one uses.

The installed binary is named **`dda`** (the crate is `dependency-dir-analyzer`).

## Toolchain & tasks: use mise

This repo uses [mise](https://mise.jdx.dev) both to install the toolchain and as
the task runner. The Rust version is pinned in `mise.toml`.

```bash
mise install        # install the pinned Rust toolchain
mise tasks          # list available tasks
mise run build      # cargo build
mise run test       # cargo test
mise run lint       # cargo clippy -D warnings
mise run fmt        # cargo fmt --all
mise run fmt-check  # cargo fmt --all --check
mise run ci         # fmt-check + lint + test + release build (what CI runs)
mise run run -- ~/code   # run the CLI against ~/code
```

Prefer `mise run <task>` over invoking `cargo` directly so behaviour matches CI.
If you add a workflow developers will repeat, add it as a task in `mise.toml`.

## Layout

```
src/
  main.rs       # CLI entry point: parse args, run scan, dispatch output
  cli.rs        # clap argument definitions + human size parsing (`parse_size`)
  scanner.rs    # filesystem walk, dependency-dir patterns, parallel sizing
  report.rs     # Report struct + table/JSON rendering
.github/workflows/
  ci.yml        # lint/test/build on Linux, macOS, Windows via mise
  release.yml   # cross-compiled release binaries on tag push
.claude/
  hooks/session-start.sh   # installs mise + deps in Claude Code on the web
  settings.json            # registers the SessionStart hook
mise.toml       # toolchain + tasks
```

## How the scanner works

- `scanner::PATTERNS` is the list of known dependency-directory names mapped to
  an ecosystem label. To support a new tool, add an entry there (and ideally a
  test case). Matching is by **exact, case-sensitive base name**.
- When a matching directory is found, the walk does **not** descend into it: the
  whole subtree is sized as one unit, so a nested `node_modules` inside another
  is not double-counted.
- Sizing is parallelised across matches with `rayon`.
- Unreadable entries produce a warning on stderr and are skipped; the scan does
  not abort.

## Conventions

- Keep `cargo fmt`, `cargo clippy -D warnings`, and `cargo test` clean — CI
  enforces all three. Run `mise run ci` before pushing.
- Add unit tests next to the code (`#[cfg(test)] mod tests`) for new behaviour.
- Keep dependencies minimal and pure-Rust where possible so cross-compilation
  stays painless.

## Releases

Releases are produced by `.github/workflows/release.yml` when a `v*.*.*` tag is
pushed. It cross-compiles for Linux (x86_64, aarch64), macOS (x86_64, aarch64)
and Windows (x86_64), then attaches archives + SHA-256 checksums to a GitHub
Release. To cut a release:

```bash
# bump version in Cargo.toml first, then:
git tag v0.1.0
git push origin v0.1.0
```

## Claude Code on the web

`.claude/hooks/session-start.sh` runs at session start in the remote
environment (`CLAUDE_CODE_REMOTE=true`). It installs mise if absent, runs
`mise install`, and puts the toolchain on `PATH` so tests and linters work
immediately. It is a no-op locally.
